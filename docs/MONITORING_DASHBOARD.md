## 2. 仪表板功能

### 实时监控指标

#### 性能指标

- **事件处理延迟**：处理每个直播事件的平均时间（目标 < 100ms）
- **决策制定延迟**：Runtime 决策的平均时间（目标 < 50ms）
- **OBS 操作延迟**：执行 OBS 动作的平均时间（目标 < 200ms）

#### 业务指标

- **平均注意力**：观众注意力的平均值（0-1，目标 > 0.5）
- **事件吞吐量**：每秒处理的事件数量
- **场景切换次数**：自动场景切换的总次数
- **转化率**：观众互动转化率

#### 系统指标

- **内存使用**：当前内存使用量（MB）
- **CPU 使用率**：当前 CPU 使用百分比
- **错误率**：错误事件占总事件的比例（目标 < 1%）
- **熔断器状态**：各模块的熔断器状态

### 健康检查

#### 检查项

- **OBS 连接**：OBS WebSocket 连接状态
- **事件队列**：事件队列是否正常
- **内存状态**：内存使用是否正常

#### 健康状态

- ✅ **健康**：所有检查项正常
- ⚠️ **警告**：部分检查项异常，但系统仍可运行
- ❌ **不健康**：关键检查项异常，需要立即处理

### 告警规则

#### 内置告警规则

| 告警名称 | 触发条件 | 严重程度 |
|---------|---------|---------|
| `high_error_rate` | 错误率 > 5% | 高 |
| `low_attention` | 平均注意力 < 0.3 | 中 |
| `high_latency` | 事件处理延迟 > 500ms | 高 |
| `circuit_breaker_open` | 熔断器打开 | 高 |
| `obs_disconnected` | OBS 连接断开 | 高 |
| `high_memory_usage` | 内存使用 > 80% | 中 |

#### 告警通知

告警触发后，会在仪表板顶部显示告警信息，包括：
- 告警名称
- 触发时间
- 当前值
- 建议操作

## 5. 配置选项

### 环境变量

在 `.env` 文件中配置：

```bash
# 监控配置
DASHBOARD_PORT=8080        # 仪表板端口
LOG_LEVEL=info             # 日志级别 (debug/info/warn/error)
```

### 告警阈值

在代码中修改告警阈值：

```typescript
// src/monitoring/alert-manager.ts
const ALERT_RULES = [
  {
    name: 'high_error_rate',
    condition: (metrics) => metrics.errorRate > 0.05,  // 5%
    severity: 'high',
  },
  {
    name: 'low_attention',
    condition: (metrics) => metrics.avgAttention < 0.3,  // 0.3
    severity: 'medium',
  },
  // ...
];
```

## 6. 性能优化

### 降低监控开销

1. **增加采集间隔**：
   ```typescript
   // 默认 10 秒
   METRICS_COLLECTION_INTERVAL = 10000;
   ```

2. **减少历史数据保留**：
   ```typescript
   // 默认保留 1000 条
   MAX_METRICS_HISTORY = 1000;
   ```

3. **禁用部分指标**：
   ```typescript
   // 在配置中禁用不需要的指标
   ENABLE_DETAILED_METRICS = false;
   ```

### 提高响应速度

1. **使用缓存**：
   - 缓存频繁访问的数据
   - 减少重复计算

2. **异步处理**：
   - 异步收集指标
   - 不阻塞主流程

## 7. 故障排查

### 仪表板无法访问

**检查清单**：
1. 服务是否正在运行？
2. 端口是否被占用？
3. 防火墙是否阻止访问？

**解决方法**：
```bash
# 检查端口占用
netstat -ano | findstr :8080

# 重启服务
npm run start
```

### 指标数据不准确

**检查清单**：
1. 数据采集是否正常？
2. 是否有大量错误？
3. 内存是否充足？

**解决方法**：
```bash
# 查看日志
# 检查是否有错误信息

# 重启服务
npm run start
```

### 告警频繁触发

**检查清单**：
1. 阈值是否合理？
2. 是否有性能问题？
3. 是否需要调整规则？

**解决方法**：
- 调整告警阈值
- 优化系统性能
- 禁用不必要的告警规则

## 8. 最佳实践

### 生产环境建议

1. **监控频率**：10-30 秒采集一次
2. **历史数据**：保留最近 1 小时数据
3. **告警通知**：集成企业微信/钉钉
4. **日志级别**：使用 `info` 或 `warn`

### 开发环境建议

1. **监控频率**：5-10 秒采集一次
2. **历史数据**：保留最近 10 分钟数据
3. **告警通知**：仅在仪表板显示
4. **日志级别**：使用 `debug`
